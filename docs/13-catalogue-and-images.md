# 13. Catalogue, age groups and product images

## 13.1 Age groups

The shop is browsed by five age groups. A group is a named run of size codes, defined once in
`packages/config/src/age-groups.ts` and used by the homepage cards and the shop filter (`/shop?age=toddler`).
There is no separate "age group" column: a product belongs to every group whose sizes it is sold in.

| Group        | Ages         | Size codes      |
| ------------ | ------------ | --------------- |
| Newborn      | 0-3 months   | `0-3M`          |
| Early infant | 3-6 months   | `3-6M`          |
| Mid infant   | 6-12 months  | `6-9M`, `9-12M` |
| Toddler      | 12-18 months | `12-18M`        |
| Big toddler  | 18-24 months | `18-24M`        |

Sizes are a guide. Fit varies by garment and by baby, and the pages say so.

The shop filters by age group, category, size, price range (RF), stock and search text, sorts by newest, price or
name, and pages through results ("Next page"). Colour is chosen on the product page, where each colour and size is
its own variant with its own SKU, price and stock.

## 13.2 The development catalogue

`pnpm --filter @bambino/api db:seed` (development and staging only; it refuses production) now loads, besides the
four original demo products, `seedExtendedCatalogue` (`database/seeds/extended-catalogue.ts`):

- 33 products across every age group, in 16 categories (bodysuits, sleepwear, trousers, shirts, rompers, dresses,
  outerwear, swimwear, blankets and sleep sacks, hats and mittens, socks and booties, bibs, shoes, underwear and
  gift sets), with 2 to 4 colours and the sizes of their age groups, so 324 variants, each with stock.
- SKUs follow `SEED-<age>-<type>-001-<colour>-<size>`, for example `SEED-NB-BOD-001-WHI-03M`.
- Everything is **placeholder**. Names end in "(seed)", prices are sample prices, and no material, certificate or
  sustainability claim is made. The placeholder guard finds these rows, so a production database reports "not ready"
  until they are removed. Replace them with real products in the admin before launch.

The seed is idempotent. To add more, extend the `TYPES` list in that file.

## 13.3 Product images: what is and is not done

**No product has a photo yet, and none were generated by this project.** The build environment has no image
generator, and images must not be invented to look finished. Until a product has an image the site shows its
drawn placeholder.

What exists to make adding them quick:

1. **Admin, one product at a time.** Products, then the product, then upload (JPEG, PNG or WebP, up to 5 MB).
2. **Bulk, from a folder.** For a catalogue of dozens of products:

```bash
# 1. A photo brief for every product that has no image: prompts, safety wording and the file name to use.
pnpm --filter @bambino/api catalogue:images brief catalogue-images
#    writes catalogue-images/briefs.md and briefs.json

# 2. Make the pictures with an image tool or a photographer; save each with the file name from the brief:
#       seed-ext-bod.jpg      main image of that product
#       seed-ext-bod-2.jpg    second view   (-2 to -9)

# 3. Upload and attach them (writes to the database and object storage in the environment: staging first).
pnpm --filter @bambino/api catalogue:images import catalogue-images
```

The import skips, and reports, a file whose product does not exist, a file over 5 MB, and a position that already
has an image, so it can be re-run safely. Images are stored under `products/<product id>/` in the public bucket
(`STORAGE_BUCKET`), run `storage:init` once first. Alt text is the product name (and "view N").

Rules for the pictures (they are in every brief): square 1:1, soft natural light, a clean pale background, accurate
garment details, no logos or brand names, no text, no loose neck ties or detachable small parts, and nothing that
suggests an unsafe sleep setup. For real stock, photograph the real garment: a picture must not promise a colour,
fabric or feature the product does not have.

## 13.4 Not built yet

- A **colour filter** on the shop page (colour is currently chosen on the product page).
- **Best sellers** on the homepage (needs real sales data; the section would otherwise be invented).
- Images per **colour**: images belong to the product, not to a variant, so choosing a colour does not change the
  picture. A per-colour gallery needs a schema change (`product_images.variant_color`).
- A separate **gift-set bundle** model (a set is a product today, not a list of included products).
- Real prices, stock, materials and care text: the admin product form takes them; the seed does not pretend to know.
