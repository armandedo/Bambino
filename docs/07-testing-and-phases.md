# 7. Testing strategy and development phases

## 7.1 Testing strategy

| Level       | Tool                                 | Runs against                                                  | Covers                                                                                                                                                                                                                                                                                                            |
| ----------- | ------------------------------------ | ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Unit        | Vitest                               | Pure functions                                                | Money, pricing, discounts, credit calculation, sizing rules, every lifecycle, permission catalogue                                                                                                                                                                                                                |
| Database    | Vitest + PGlite                      | Real PostgreSQL semantics in-process, every migration applied | Constraints, triggers, partial indexes                                                                                                                                                                                                                                                                            |
| Contract    | Vitest + graphql-js                  | The SDL                                                       | Required operations exist, enums match `@bambino/types`, every operation is guarded, no customer input carries an amount                                                                                                                                                                                          |
| Integration | Vitest + PGlite                      | The GraphQL API executed in-process with mock providers       | Registration, login, catalogue, cart, checkout, payment (success, failure, timeout, replayed webhook), subscription, return, exchange, authorization (another user's ids return `NOT_FOUND`)                                                                                                                      |
| End to end  | Playwright                           | Web + API + PostgreSQL                                        | Journey A: register → baby profile → sizing → subscribe → checkout → mock payment → order. Journey B: subscriber returns outgrown garments → approved → received → inspected → credit → next size → replacement order. Journey C: admin receives return → inspects → sets condition → garment available for reuse |
| Mobile      | Component tests; Maestro flows later | Expo app                                                      | Journey A on device                                                                                                                                                                                                                                                                                               |
| CI          | GitHub Actions (Phase 9)             | PostgreSQL 18 service container                               | All of the above on every push, plus type-check, lint, `prettier --check`, build, and a check that migrations match the schema                                                                                                                                                                                    |

Rules: no test may depend on a real payment, email or delivery provider. Seed and test data use the
`seed.test` email domain and `SEED`/`TEST` prefixes so they are recognisable anywhere.
